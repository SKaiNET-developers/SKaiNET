# Training Feature — Implementation Plan (E2E)

This plan turns the Product Requirements (see `train.md`) into actionable, checkable tasks grouped by workstreams. It reflects the current code state and gaps, and targets an end-to-end minimal SGD training on CPU.

## 1. Current Status (as of 2025-12-11)

- Tensor gradient plumbing
  - [x] `Tensor` exposes `gradState`, `requiresGrad`, `grad`, `accumulateGrad()`, `zeroGrad()` (see `skainet-lang-core/.../tensor/Tensor.kt`).
  - [x] `GradState` exists and is threaded through CPU tensors and views (see `GradState.kt`, `DefaultCpuOps`, `SlicedTensorView`, `CopyMaterializationStrategy`, `LazyMaterializationStrategy`).
  - [x] `ModuleParameter` syncs `requiresGrad` to backing tensor (see `ModuleParameters.kt`).
  - [ ] No actual backward graph or gradient computation; `accumulateGrad` is only a holder.

- Tape/graph and hooks
  - [x] `TapeRecorder` collects forward module-level specs only (diagnostic; no gradients).
  - [x] `DefaultExecutionTape` can build `ComputeGraph`.
  - [x] `ExecutionTape.toComputeGraph()` delegates to `DefaultExecutionTape.toComputeGraph()`; otherwise returns empty `DefaultComputeGraph` (see `skainet-compile-dag/.../tape/extensions.kt`).
  - [ ] No autograd tape/backward pass implemented.

- Losses and helpers
  - [x] `CrossEntropyLoss` implemented with `logSoftmax`, reductions.
  - [x] `evaluateLoss(model, loss, inputs, targets, ctx, reduction)` utility exists.

- Optimizer / Training pipeline
  - [ ] No `Optimizer` API or SGD implementation.
  - [ ] No `trainStep` or minimal training loop helper.

- Tests/examples
  - [x] Forward-only examples and tests exist (e.g., sinus approximator graph export tests).
  - [ ] No op gradient tests; no end-to-end training test proving loss decrease.

## 2. Workstream A — Autograd Foundations (FR1, FR2)

1. Tensor and parameter readiness
   1. [x] Ensure tensors expose `requiresGrad`, `grad`, zero/accumulate.
   2. [ ] Add a light `Parameter` wrapper (id/name) and `Module.trainableParameters(): List<Parameter>` to enable optimizer registration.
   3. [ ] Propagate `requiresGrad` via module builders; default trainable for weights/biases, non-trainable for inputs unless specified.

2. Adjoint rules (limited op set)
   1. [x] Implement backward registry and adjoint functions via `DifferentiableTensorOps` generated by KSP.
   2. [x] Cover broadcasting semantics in adjoints where applicable (e.g., `matchShape` helper).
   3. [ ] Numeric gradient checks per op (tiny tensors) with tolerances.

3. Gradient tape and reverse traversal
   1. [x] Extend/introduce `DefaultGradientTape`: record op traces with links to inputs/outputs and their backward closures.
   2. [x] Implement reverse-mode pass: seed dLoss/dOut = 1 for scalar loss (or broadcasted ones), traverse in reverse topological order, accumulate grads into each tensor's `gradState`.
   3. [ ] Guard by `Phase.TRAIN` and `requiresGrad` for low overhead during eval.
   4. [ ] Provide `zeroGrad()` utility across a set of parameters.

## 3. Workstream B — Optimizer API + SGD (FR3)

1. Optimizer surface
   1. [x] Introduce `Optimizer` interface: `addParameter`, `zeroGrad`, `step`.
   2. [x] Provide tiny factory: `sgd(lr, momentum = 0.0, weightDecay = 0.0)`.

2. SGD implementation
   1. [x] Basic SGD with in-place-style update (create-new-and-reassign if tensors are immutable in modules).
   2. [x] Optional momentum buffers per parameter.
   3. [x] Optional weight decay for parameters flagged for decay.

3. Wiring and safety
   1. [x] Decide mutation semantics: if tensors are immutable, reassign `ModuleParameter.value` after computing updated tensor; ensure `gradState.requiresGrad` preserved.
   2. [x] Unit tests for `zeroGrad`, momentum behavior, weight decay.

## 4. Workstream C — Training Helper / DSL (FR4)

1. Minimal helper
   1. [x] Implement `trainStep(model, loss, optimizer, ctx, x, y)`:
     1. [x] Enable gradient tape, forward pass, compute loss.
     2. [x] Backward pass to populate grads.
     3. [x] `optimizer.step()` then `optimizer.zeroGrad()`.
     4. [x] Return loss value (tensor) and optional metrics.

2. Optional DSL façade (experimental)
   1. [x] `training { model { … } loss { … } optimizer { sgd(lr) } }` builder that wires objects and runs a simple loop; keep internal/experimental to avoid early API lock-in.

## 5. Workstream D — Tape/Graph Parity (FR5)

1. [ ] Ensure gradient-enabled runs still produce usable forward traces for graph export.
2. [ ] Verify `ExecutionTape.toComputeGraph()` returns non-empty graph when using training context.
3. [ ] Regression test that recorded run produces nodes/edges.

## 6. Workstream E — Tests & Example (FR6)

1. Unit tests — gradients
   1. [ ] Finite-difference checks for each supported op’s adjoint (small shapes, multiple broadcast cases).

2. Integration test — minimal model
   1. [ ] Build 2-layer MLP (or sinus approximator) with CPU context.
   2. [ ] Train with SGD on a tiny toy task (XOR or 1D sinus) and assert monotonic or thresholded loss decrease within <500 steps.
   3. [ ] Seed RNG for determinism and document expected tolerance.

3. Examples and docs
   1. [ ] Add concise example showing one `trainStep` and a short loop using `DirectCpuExecutionContext`.
   2. [ ] Update README/docs to point to the example and `train.md`/this plan.

## 7. Non-functional and Safety

1. [ ] Clear error when an unsupported op participates in a gradient path (explicit message pointing to unsupported adjoint).
2. [ ] Performance: keep naive autograd acceptable for small MLP; isolate for future backend acceleration.
3. [ ] API stability: mark training DSL as experimental/internal.

## 8. Acceptance Criteria Mapping

1. [ ] SGD trains a minimal MLP on CPU with loss reduction in bounded steps; integration test passes.
2. [ ] Gradients for supported ops match finite differences within tolerance.
3. [ ] `ExecutionTape.toComputeGraph()` returns a populated graph from a training run.
4. [ ] Documentation shows forward → backward → step usage and a tiny loop.
