= Benchmark baseline
:description: Reference JMH numbers for the matmul, elementwise and reduction hot paths, to compare against when a change touches dispatch or storage.

These are the numbers a change to kernel dispatch or tensor storage is compared against.
xref:skeep:003-unified-tensor-storage.adoc[SKEEP-003] sets the budget: matmul within noise,
elementwise at most 3 % slower.

== How to compare

. Run the suite on the commit before your change and on the commit with it, on the same machine,
  with nothing else building:
+
[source,bash]
----
./gradlew :skainet-backends:benchmarks:jvm-cpu-jmh:jmh \
  -PjmhIncludes='sk.ainet.bench.(MatmulBench|KernelMatmulBench|QuantizedMatmulBench|ElementwiseAdd1MBench|Reductions1MBench).*'
----
+
The results are in `skainet-backends/benchmarks/jvm-cpu-jmh/build/results/jmh/results.txt`.
`scripts/pr-gate.sh --bench` runs the whole suite.
. Put both tables in the pull request. The table below tells you what the numbers looked like on
  the reference machine; numbers from another machine are only comparable with each other.
. When a change moves a number on purpose, record a new baseline here in the same pull request.

Not part of this baseline: `:skainet-lang:skainet-lang-core:jvmBenchmark` (`StorageBenchmarks`,
`TensorBenchmarks`, `TurboQuantBenchmarks`). With the module's default iteration settings a full
run takes hours; run it filtered per class when a change touches the storage hot paths.

`thrpt` is throughput, higher is better; `avgt` is the average time per call, lower is better.

One thing the table shows that is not a storage matter: on this Linux machine `MatmulBench` with
`blasEnabled=true` is about seven times slower than the Panama kernel at every size
(8.5 ms against 1.3 ms at 256). BLAS routing is off by default outside macOS.

The baseline recorded on 2026-08-22, before the storage migration, was removed with
`docs/design/` (#1106); it is in the history at commit `3c0ee71d`. It was taken on the same
machine with OpenJDK 25, so the two are not directly comparable.
